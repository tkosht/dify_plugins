Images are fetched only from operator-approved HTTPS file endpoints and sent to the fixed internal OCR service with TLS verification and literal IP pins. OCR text and coordinates return to Dify and the selected model; Dify/provider conversations, execution logs and observability may retain copies. Service cleanup does not delete those copies or alter their retention.

The independent Tool variant refuses unsupported execution-context transports. The dedicated Agent variant uses authenticated SDK app identity, an explicitly configured system workflow-run binding, private adapter configuration and strict six-argument model calls. Model credentials remain in Dify's normal model-provider path. Fixed preparation and cleanup are outside model choices. No external OCR, crop-image model input or telemetry is added by this component.

Standard Dify sandbox validation with a deterministic local fake provider and real OCR proves orchestration, not production confidential-data security or real-model quality. Deployment CA trust, endpoints, credentials, runtime configuration, egress and all retention layers need operator verification. Private configuration, keys, signed URLs and deployment identities must not be packaged or logged. Native Dify execution IDs may already be recorded as execution metadata; that is distinct from storing credentials or authorization capabilities.
